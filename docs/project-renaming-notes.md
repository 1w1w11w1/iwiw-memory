# 项目重命名决策记录草案

## 为什么考虑重命名

`SelfEcho` 强调“自我回声、倾听、记录、长期记忆”。这个名字适合当前的树洞与记忆系统气质，但项目未来目标已经扩展为：

- 成熟个人智能体。
- 可观察、可测试、可回滚的 agent harness。
- 能区分用户是在倾诉，还是需要解决问题。
- 能进行问题理解、规划、执行、纠错和追踪。
- 以强记忆管理系统支撑持续上下文。

因此，如果继续使用 SelfEcho，容易让项目被理解成“树洞 / 陪伴 / 记忆应用”，而不是“有情绪承接能力的个人智能体系统”。

## 命名原则

新名字应满足：

- 能容纳记忆、对话、规划、工具、工作流和 harness。
- 不把项目限定为树洞、日记、心理陪伴或纯聊天。
- 不显得像企业效率 SaaS。
- 保留个人连续性、理解、陪伴、协作的气质。
- 适合作为 GUI 品牌名、目录名、API title 和配置前缀。
- 尽量短，英文可读，中文语境中也不别扭。

## 不推荐的命名方向

- 纯情绪陪伴类：容易削弱 agent 和工作流目标。
- 纯效率工具类：容易丢掉“倾听与记忆”的独特性。
- 过度技术类：如直接叫 Harness、AgentCore，缺少个人产品气质。
- 过度宏大类：容易像通用平台，而不是个人智能体。

## 候选方向

### 方向 A：保留 SelfEcho，但重新定义

含义：

> SelfEcho = 能记住并回应用户连续性的个人智能体。

优点：

- 已有代码、目录、数据和 UI 都使用该名。
- “Echo”仍能表达长期记忆和反馈。
- 改动成本最低。

缺点：

- 需要在 README 和产品文案中反复强调它不是纯树洞。
- 名字天然偏向倾听和记录，对执行型 agent 表达较弱。

适合条件：

- 希望短期少做迁移。
- 接受通过副标题弥补定位，例如 “SelfEcho Agent”。

### 方向 B：SelfEcho 作为功能名，新项目另起主名

结构：

```text
新项目名
  - SelfEcho Mode：倾听与记录
  - Work Mode：问题处理与规划
  - Memory Layer：长期记忆
  - Agent Harness：运行与工具
```

优点：

- 保留 SelfEcho 的情感资产。
- 新项目名可以承载更完整的 agent 定位。
- “树洞”自然下降为一个 mode。

缺点：

- 需要一次清晰迁移。
- 文档和 GUI 文案要重新梳理。

适合条件：

- 你已经确定项目要从记忆实验转向完整个人智能体。

### 方向 C：围绕“连续性 / 记忆 / 行动”命名

候选词根：

- Continuum：连续性，但容易和旧历史系统混淆。
- Loom：编织上下文和行动，温和但有结构感。
- Thread：线索、会话、连续任务，技术气质适中。
- Anchor：锚点、稳定、记忆，但执行感弱。
- Compass：判断和方向，但记忆感弱。
- Praxis：实践、行动，但偏哲学。
- Mnemo：记忆，但偏技术和生硬。
- Relay：接力、传递、连续执行，但个人气质稍弱。

## 初步候选名

这些只是方向，不是最终建议：

- `EchoPilot`：保留 Echo，增加 agent/导航意味。
- `SelfPilot`：个人智能体感强，但略普通。
- `MindLoom`：记忆和工作流编织感强，偏温和。
- `ThreadMind`：会话线索 + 认知处理，适合记忆和任务。
- `RecallOS`：强调记忆操作系统，但稍硬。
- `Continuum`：连续性强，但需要避开旧系统联想。
- `AnchorMind`：稳定记忆与问题处理，执行感一般。
- `Praxis`：行动和实践，树洞气质弱。
- `Eidolon`：自我映像感强，但太文学化。
- `SecondSelf`：个人智能体定位明确，但容易过度拟人化。

## 当前较稳妥的短期方案

短期不建议直接全局重命名。更稳妥的方案是：

1. GUI 和 README 中先把旧的树洞定位改为更宽的智能体副标题。
2. 文档中明确 “SelfEcho Mode / 倾诉模式” 是功能分支。
3. 新增 `selfecho_agent/` harness 后，再决定主项目是否改名。
4. 如果改名，先保留数据目录兼容层，不直接移动用户数据。

建议临时副标题：

```text
SelfEcho
personal memory agent
```

或：

```text
SelfEcho
memory-backed personal agent
```

## 如果正式改名，需要迁移的对象

- GUI brand 文案。
- README 标题和项目描述。
- `selfecho_api/`、`selfecho_session/`、未来 `selfecho_agent/` 包名。
- `selfecho_data/` 数据目录。
- `selfecho_config/` 配置目录。
- API title。
- 文档中的 SelfEcho 引用。
- 旧数据目录的兼容读取和迁移提示。

正式改名建议分两步：

1. 先改产品文案和 README，代码包名保持兼容。
2. 再做目录迁移，并保留旧目录读取 fallback。
