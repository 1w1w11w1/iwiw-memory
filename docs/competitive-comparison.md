# 记忆系统竞品结构对比：经验吸取与不足清单

> 对比对象：本项目（E:/desktop/111，纯 Python 确定性记忆系统）vs 七家 DSH 插件（源码级审计，2026-09）+ Mem0/Codex 参照。
> 事实基础：用户提供的竞品审计表 + 本项目实际代码状态。

## 1. 六维度结构对比

| 维度 | 本项目 | 头部做法 | 差距判定 |
|---|---|---|---|
| 写入捕获 | 规则触发（triggers 高信号词表）→ LLM 提取 → 自动入库 | hook 会话事件全覆盖捕获（meow/graph/layered）；mnemon 用宿主 LLM 判断 | **有差距**：规则词表会漏（如"我下周要去上海出差"不在高信号模式） |
| 记忆组织 | 三值分级（core/normal/archive）+ 扁平单表事实 | meow 七层；StrataGate L0-L5 旧记忆变浅索引；layered L0 捕获→L3 画像蒸馏；mnemon 四图（temporal/entity/semantic/causal） | **有差距**：扁平无结构化关联，实体/时间/因果查询靠词面+同义词硬扛 |
| 检索召回 | FTS + jieba + 同义词表 + SessionState 回指 + 结构化加权（全确定性、零模型） | graph/layered：向量+BM25 真混合；meow：交集×idf×覆盖率×艾宾浩斯×importance 打分 | 各有取舍：我们零依赖可解释，但无词面近义召回弱于向量混合 |
| 注入方式 | system 层：core 常驻 + 每轮联想 top-3 + DSC 检查点 + 尾部保留 | layered 每步 pre-step 自动注入；graph 上下文接管（最近 5 轮+图召回）；meow 压缩后重注入 | **基本持平**；缺"压缩后高分记忆重注入" |
| 整理维护 | 手动 /maintain（归档候选 pending）+ 手动 merge；**无自动整理** | meow 空闲 dream 三阶段（自动）；memory-evolve 回合内 advisor 自审；StrataGate 只强化实际使用的记忆 | **最大差距**：无后台自动整理，记忆库质量不随使用进化 |
| 可审计性 | mutation 全留痕（version_id/audit_id/changed_rows）+ 版本回滚 | StrataGate 事件卡带来源；多数插件无完整版本/审计 | **我们领先**：mutation 契约是最完整的 |
| 证据评测 | 自建评估（联想 10/10、回指 42.9%、核心 3/3），非标准 | StrataGate LoCoMo 80.46%；graph-memory token −70.58% | **有差距**：无可外部引用的标准数字 |
| 部署依赖 | 纯 Python + jieba + SQLite，零模型零向量 | meow 零原生依赖；mnemon Go 单二进制零 API key | 持平偏优（删向量后） |

## 2. 我们的真实优势（有依据，不是自夸）

1. **mutation 契约**：version_id/audit_id/changed_rows + 版本回滚，七家里只有 StrataGate 的"事件卡带来源"接近，无人做到完整变更审计。这是"白箱可追溯"的硬基础。
2. **SessionState 回指联想（L2）**：审计的七家没有一家做"会话状态驱动的指代回指"——他们的召回都是"相似度/关键词"式。我们的回指机制（"那件事"→最近/高频讨论话题→记忆）是差异化的。
3. **DSC 确定性压缩**：借鉴 Codex，插件生态里 graph-memory 的"上下文接管"最接近，但我们的检查点（话题/决策/任务）无 LLM 依赖。
4. **零模型检索**：删向量后全链路确定性，部署比"向量+BM25 混合"系轻一个量级。

## 3. 不足清单（按"从谁学、代价、收益"排序）

| # | 不足 | 从谁学 | 学什么 | 代价 | 预期收益 |
|---|---|---|---|---|---|
| G1 | **使用强化缺失**：access_count/last_access_at 字段存在但 touch_memory 无调用方，"实际使用的记忆"不会被强化 | StrataGate（只强化实际使用的记忆） | 检索命中即 touch；维护时按使用数据自动提升/降级 priority | 低（字段与函数已在） | 记忆库质量随使用自动进化；同时落地"事后异步审查" |
| G2 | **自动后台整理缺失**：只有手动 /maintain；meow 的空闲 dream 三阶段是自动的 | meow（dream）/ memory-evolve（advisor） | 空闲/周期触发整理：归档候选 + 使用强化 + 重复合并建议 | 中（整理策略设计） | 记忆库免手动维护；与 G1 合并实现 |
| G3 | **写入覆盖面漏**：规则词表触发会漏非模式句（"我下周要去上海出差"） | 头部共性（hook 全捕获）+ mnemon（宿主 LLM 判断） | 放宽触发或每轮轻量判断（LLM 一次调用判定是否值得提取） | 中（LLM 成本/延迟） | 捕获覆盖率接近头部 |
| G4 | **无来源引用**：记忆行内无"提取自哪段对话" | StrataGate（事件卡带来源） | memories 加 source 字段（来源摘要/位置） | 低 | 白箱可追溯下沉到行内；支撑事后审查 |
| G5 | **压缩后无高分重注入**：DSC 检查点只含话题/决策/任务 | meow（压缩后重注入） | 检查点视图附带 core + 高分记忆的 slug+一行摘要 | 低 | 压缩后关键记忆不丢失 |
| G6 | **无实体/时间结构**：实体关系查询（弟弟在哪读书）靠同义词硬扛 | mnemon（四图）/ graph-memory（图节点） | 轻量版：memories 加 entities/event_date 结构化字段（提取时 LLM 顺带产出），不做图数据库 | 中 | 实体/时间查询从"同义词碰运气"变"字段匹配" |
| G7 | **无标准评测数字** | StrataGate（LoCoMo 80.46% 协议开源） | 跑 LoCoMo 单对话评测 | 中 | 可引用数字 + 与竞品同口径对比 |

## 4. 取舍判断

**先做 G1+G2（合并为一个"使用驱动自动整理"）**，理由：
- 三个头部（StrataGate/meow/memory-evolve）各自验证了"使用驱动 + 自动整理"是记忆质量进化的关键，且我们有现成数据字段（access_count）与审查框架（pending），只缺把它们连起来的策略层；
- 它同时是用户判断"沉默写入 + 事后异步审查"的落地载体：写入已沉默，缺的正是异步审查与自动升降级；
- 成本最低（无新依赖、无 schema 大改）。

**其次 G4（来源引用，低成本）与 G5（压缩后重注入，小改）**，两者都是白箱理念的直接落点。

**暂缓 G6（实体图谱）**：个人记忆量级下图的收益未证实，先用字段化元数据探路；**G7（LoCoMo）独立推进**（已在推进讨论中定位为证据优先），与 G1-G5 解耦。

## 5. 明确不吸取的

- **向量/BM25 混合检索**：已论证是联想的错配工具（associative-recall-architecture.md），且头部混检系的打分调参成本（meow 五因子、graph 三通道）正是我们刚删掉的技术债形态。
- **多层数量膨胀**（七层/L0-L5/五轨）：分级三值 + 扁平表在个人记忆量级下足够，层级越多维护与审计越复杂。
