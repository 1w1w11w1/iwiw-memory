# 联想（Associative Recall）架构评估与重构方向

> 核心问题：联想性能很重要，但向量语义是不是它的正确实现？
> 定量结论：**联想的主体不依赖向量；向量只贡献"无词面线索的语义近义召回"这一小块，且这恰是最可替代的部分。**

## 0. 一句话判断

**向量语义是"联想"的错配工具。** 联想（associative recall）的本质是"上下文相关"，不是"语义相似"——人脑的"那件事/话赶话"靠的是会话状态与话题脉络，而不是对记忆做相似度检索。用 200MB 向量模型去实现联想，是给错误的工具付了最贵的成本。

## 1. 定量证据（实验）

禁用向量通道（VECTOR_SIMILARITY_FLOOR=2.0），仅剩 FTS + 词面，跑联想评估（10 用例）：

| 用例组 | 有向量 | 无向量（纯 FTS+词面） | 差异归因 |
|---|---|---|---|
| direct（直接关键词） | 2/2 | 2/2 | 词面足够，向量无贡献 |
| semantic（语义近义） | 3/3 | 1/3 | 向量独有贡献（-2：写代码→软件工程师、我弟→弟弟上海） |
| topic（话题联想） | 3/3 | 2/3 | 主体靠对话状态+词面；向量仅边缘贡献 |
| unrelated（反例） | 2/2 | 2/2 | 词面反例同样可靠 |
| **合计** | **10/10** | **7/10** | 向量独有 ≈ semantic 近义 2 例 |

结论：删除向量只损失"无词面线索的语义近义召回"（约 2/10 用例），而这部分可以被轻量确定性机制替代。

## 2. 联想的本质：三层信号，不是一层相似度

| 层 | 信号 | 对应机制 | 成本 | 删除向量的影响 |
|---|---|---|---|---|
| L1 词面 | 当前话语/上下文里的词 与 记忆词面 | FTS5 + 子串 + 同义词表 | 零 | 无 |
| L2 上下文状态 | 会话中讨论过的话题 / 最近引用记忆 / 已建立事实 | **会话状态检查点（DSC SessionState）** | 零（确定性） | 无 |
| L3 语义近义 | 含义相近但词面不同 | 向量（现状）→ 标签/同义词/共现图（替代） | 现状高 → 替代后近零 | 损失 2/10，可补 |

人脑联想的体感 = 主要是 L2（上下文状态）+ L1（词面），L3 只是补充。
我们之前的失败（长对话回指 25%）恰恰说明：向量对"那件事"也无能为力——它解决不了 L2，而 L2 才是联想的正解。

## 3. 正确重构方向

### 3.1 新增 L2：会话状态驱动联想（DSC SessionState）—— 联想核心

- 会话状态记录：已讨论话题（slug+主题词+时间）、最近引用过的记忆、已建立事实、进行中任务；
- 联想 = 当前话语 匹配 会话状态（最近话题优先 + 词面）+ 全局 FTS；
- "那件事"回指 = 从会话状态找"最近讨论的话题/决策"，而非向量搜"那件事"；
- 确定性、零 LLM、零模型、可测试；与压缩检查点同源（一个 SessionState 双用）。

### 3.2 保留并增强 L1：词面 FTS + 同义词表

- FTS5 已有；补一张轻量同义词/别名映射（编程↔写代码、弟↔弟弟、想↔打算），覆盖高频近义；
- 手工维护几十条即可覆盖 80% 常见近义，零模型、可解释。

### 3.3 用轻量替代替换 L3 向量

| 替代方案 | 原理 | 成本 | 覆盖 |
|---|---|---|---|
| 记忆标签 | 每条记忆离线（LLM 一次性）打 3-5 个标签；检索时匹配标签 | 离线一次，运行时零模型 | 语义类别召回 |
| 共现图 | 统计哪几条记忆常一起被检索/引用，联想时扩展 | 增量、确定性 | 关联联想 |
| 同义词表 | 高频近义映射 | 极小 | 词面近义 |

> 这三者都是确定性/统计性的，运行时无模型、可测试、可解释——符合你"干净彻底重构"的方向。

### 3.4 删除向量（技术债清零）

- 删 embedding.py、memory_chunks.vector、search_vectors、VECTOR_FLOOR、检索向量通道；
- 删 sentence-transformers 依赖（省 ~200MB 内存 + HF 下载 + CPU 推理）；
- 联想评估预期：10/10 → 7/10（L3 两块），补标签/同义词后回到 ~9-10/10，但全部确定性。

## 4. 重构后的联想链路（目标）

```
用户消息 + 会话状态（SessionState）
  │
  ├─ L1 词面：FTS5 关键词 + 子串 + 同义词表
  ├─ L2 状态：匹配最近讨论话题 / 已引用记忆 / 进行中任务
  └─ L3 轻量语义：记忆标签匹配
  │
  ▼
融合排序（确定性权重）→ 注入 system
```

## 5. 结论

你的两个诉求（保联想 + 去技术债）**不冲突**，因为向量本来就不是联想的好实现。
正确路径：**用 SessionState（DSC）补上联想的真正短板 L2，用 FTS+同义词+标签覆盖 L1/L3，删掉向量。**
联想体感不降反升（因为 L2 是它过去最缺的），技术债清零（确定性、零模型、可测试）。
