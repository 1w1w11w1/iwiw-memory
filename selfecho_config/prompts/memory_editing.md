# 记忆编辑策略

本策略用于 GUI 手动编辑、合并、删除和归档长期记忆。长期事实记忆的真源是 SQLite，不再是 `memory/*.md`。

## 统一入口

- 所有写入、编辑、合并、归档、删除和回滚都必须走 `memory_agent.db` 的 mutation 入口。
- 成功结果必须包含 `version_id`、`audit_id`、`changed_rows`。
- `changed_rows == 0` 不能展示为成功。
- 变更前版本必须写入 `memory_versions`。
- 变更事件必须写入 `memory_audit`。
- 内容变更后必须刷新或清理相关检索数据：FTS、向量 chunk、Markdown 导出缓存如存在也要同步。

## 编辑

- 编辑前展示 diff。
- 用户明确纠正记忆时，以用户最近一次明确更正为准。
- 不确定是否属于稳定事实时，先生成候选或继续观察，不要直接写入长期记忆。
- `core` 和 `important` 必须克制使用，避免启动上下文膨胀。

## 合并

- 只有明确属于同一主题时才合并。
- 合并后的目标记忆应比来源更清晰，不只是拼接文本。
- 来源记忆默认归档；永久删除只在用户明确要求时执行。

## 删除

- 删除必须可审计、可回滚。
- 删除不能导致历史版本一起丢失。
- 如果只是过时，优先归档而不是删除。
- 用户明确要求删除时优先执行，但仍必须记录版本和审计。

## Markdown 缓存

- `memory/MEMORY.md` 和 `memory/*.md` 如存在，只能作为人工可读导出缓存。
- 不要把 Markdown 文件当作写入真源。
- 不要再使用 `memory/.history/` 作为备份机制。
