# 记忆编辑策略

本策略用于 GUI 手动编辑、合并、删除和回滚记忆对象。

记忆对象分两类：

- **全量记忆材料**：原始消息、工具结果、手动记录和项目事件的包装。
- **倾向对象**：倾向观察、全局倾向 profile、项目倾向 profile。

## 统一入口

- 所有写入、编辑、合并、删除和回滚都必须走统一 mutation 入口。
- 成功结果必须包含 `version_id`、`audit_id`、`changed_rows`。
- `changed_rows == 0` 不能展示为成功。
- 变更前版本必须写入 `memory_versions`。
- 变更事件必须写入 `memory_audit`。
- 内容变更后必须刷新或清理相关检索数据：FTS、向量 chunk、导出缓存如存在也要同步。

## 编辑全量记忆材料

- 编辑前展示 diff。
- 保留来源信息：session、turn、project、source_type。
- 不把原始材料改写成总结，除非用户明确要求手动修订该材料。
- 用户明确纠正内容时，以用户最近一次明确更正为准。

## 编辑倾向对象

- 区分全局倾向和项目倾向。
- 倾向 profile 必须短，适合每轮注入。
- profile 更新必须保留来源 observation。
- 不确定是否稳定时，只写倾向观察，不直接改 profile。
- 与现有 profile 冲突时，标记 dirty 或触发 rebuild。

## 合并

- 只有明确属于同一主题时才合并。
- 合并后的目标应比来源更清晰，不只是拼接文本。
- 合并倾向观察后必须刷新对应 profile 的 dirty 状态。

## 删除

- 删除必须可审计、可回滚。
- 删除不能导致历史版本一起丢失。
- 用户明确要求删除时优先执行，但仍必须记录版本和审计。

## 导出缓存

- `memory/` 如存在，只能作为人工可读导出缓存。
- 不要把 Markdown 文件当作写入真源。
