# 倾向整理策略

本策略用于从会话片段、项目事件和手动整理请求中生成倾向观察，并在需要时编译全局 / 项目倾向 profile。

全量记忆库的原始材料由系统确定性写入，不由本策略决定是否保存。

## 输入

- 原始会话片段。
- 当前滚动摘要。
- 当前项目上下文。
- 已有全局倾向 profile。
- 已有项目倾向 profile。
- 触发类型：`observe`、`compile` 或 `rebuild`。

## 倾向类型

- `global`：跨项目长期生效的用户交流偏好、协作方式、风险敏感点和决策默认值。
- `project`：只在当前项目中生效的架构原则、重构方向、删改策略、命名偏好和实现节奏。

## 触发处理

- `observe`：提取高信号倾向观察，保持短句，保留来源，不重写整份 profile。
- `compile`：读取 dirty observations 和相关原始片段，压缩成短 profile。
- `rebuild`：在用户要求重新审视、profile 冲突或项目方向根本变化时，从指定范围重新编译 profile。

## 需要提取的内容

- 用户明确纠正 IwIw 行为。
- 用户明确表达长期偏好。
- 用户说“以后都这样”“这个项目里按这个来”。
- 项目中出现稳定设计原则或重构方向。
- 当前表达与已有 profile 冲突。

## 不要提取的内容

- 单次临时情绪。
- 没有稳定性的闲聊。
- 纯技术材料本身。技术材料应进入全量记忆库，只有其中的协作偏好或项目原则才进入倾向。
- 原始事实的改写版。事实检索由全量记忆库负责。

## 输出原则

- 倾向 profile 要短，适合每轮注入。
- 每条倾向必须有来源。
- 全局倾向和项目倾向必须分开。
- 不确定时只写 observation，不更新 profile。
- 用户最新明确纠正优先。
